Every Tick user belongs to an **organization**. Registering creates a personal org with you as its **owner**; clients, projects, tasks, tags and entries all live inside the org, so everything in this guide is shared with the people you invite.

## Roles

| Role | Can do |
| --- | --- |
| `owner` | Everything, including managing members and invites. The **last owner can never be demoted or removed** — the API refuses with a 409. |
| `admin` | Same day-to-day powers as owner: rename the org, manage members and roles, create and revoke invites. |
| `member` | Track time and use the catalog; no member/org management. |

## Members & roles

**Settings → Members & roles** lists everyone in the org with name, email, role and rate. Owners and admins can:

- Change a member's **role**.
- Set a per-member **rate override** (see below).
- **Remove** a member from the org.

### Rates per member

Each membership can carry its own $/h rate. It slots into the [Rule 2 inheritance chain](/guide/projects-clients-tasks#rule-2-rate-inheritance) between client rate and the user's personal default:

```
entry override → project → client → org member → user default
```

So a team can price one person differently across the whole org without touching any project, and each user still has a personal default (**Settings → Profile**) as the final fallback.

## Invite links

Tick sends no email — invites are **copyable links** instead:

1. An owner or admin creates an invite (email + role) under Members & roles.
2. The UI shows a `…/register?invite=TOKEN` link to copy and send however you like.
3. The register page looks the token up, prefills the email, and shows which org and role the invite is for. Registering with the token joins the existing org instead of creating a personal one.

Invites expire after **7 days** and are single-use; an expired or used link shows a clear error on the register page. Pending invites are listed and can be revoked at any time.
