## The timer bar

A sticky timer bar sits at the top of every page. Its parts, left to right:

1. **Description input** — "What are you working on?". Pressing **Enter** starts the timer; pressing Enter while it runs stops it. Edits while running sync to the server.
2. **Chain chip** — appears once something is attached, showing the whole derived chain (`Task · Project · Client`) as a single removable chip. Removing the chip returns the entry to "simple".
3. **`+` button** — opens a menu (Client / Project / Task, each with counts) that leads into the [picker](#the-picker).
4. **Billable toggle** — shows the resolved rate ("$110/h") when billable, "Not billable" otherwise. The rate comes from the server via [rate inheritance](/guide/projects-clients-tasks#rule-2-rate-inheritance).
5. **Clock** — `HH:MM:SS`, tabular numerals, accent-colored while running.
6. **Start/stop** — an outlined circular button; it glows softly while the timer runs.

Rules worth knowing:

- The running timer is just a `time_entries` row with `end IS NULL`. A partial unique index guarantees **at most one running timer per user** — starting a second one returns HTTP 409, and the UI re-syncs instead of double-tracking.
- Stopping with **less than one second** elapsed discards the entry rather than logging noise.
- Stopping otherwise inserts the entry at the top of Today and navigates to the Time page.
- The server is the source of truth: reload the page mid-timer and the clock picks up where it was.

### Simple ↔ project mode

There is no mode switch. Every entry is "simple" until you attach a client, project or task via the `+` button. Attach a task and the project and client come along automatically (they are derived, not copied — see [Rule 1](/guide/projects-clients-tasks#rule-1-store-only-the-deepest-reference)).

## The picker

One dialog serves the timer bar, the manual-entry dialog and the selection bar's *Move to…*:

- Tabs **Client / Project / Task** (done tasks are hidden).
- Search is autofocused; rows show a client color dot, the name, and a context sub-line (task → "Project · Client", project → its client, client → project count) plus rate or estimate on the right.
- No match? A dashed **Create "{query}"** row creates the item inline and picks it immediately.
- Full keyboard support: `↑` `↓` move, `↵` picks, `esc` closes.
- Long lists paginate at 50 rows with an "n more…" row.

## Manual entries

**Manual entry** (button in the Time page header) opens a dialog with description, an attach field (opens the picker), a billable toggle with the resolved rate, **Date / Start / End / or Duration** fields, and comma-separated tags.

All four time fields accept free text and parse live. A status line under the fields shows the interpretation ("Sat, Mar 14, 2025 · 9:00am – 11:30am · 2h 30m") and turns accent-colored when valid; **Add entry** stays disabled until the fields resolve. A duration without a start time logs from 9:00 and says so.

### Date, time and duration formats

| Field | Accepted forms | Examples |
| --- | --- | --- |
| Date | ISO | `2025-03-14` |
| | US numeric, `/` or `.`, year optional (2-digit = 20xx) | `3/14/25` · `3.14.2025` · `3/14` |
| | Month-day, year optional, ordinals OK | `mar 14` · `march 14th, 2025` |
| | Day-month | `14 mar` · `14th march 2025` |
| | Relative words | `today` · `yesterday` |
| | Weekday = most recent **past** occurrence | `tue` · `last tue` · `tuesday` |
| | Empty | means today |
| Start / End | 24h or 12h clock, minutes optional, `a`/`p` shorthand | `9` · `9:30` · `2pm` · `14:15` · `2:30 pm` · `9a` |
| Duration | Hours (decimal OK), minutes, combos, `h:mm` | `2h 30m` · `1.5h` · `90m` · `1:30` · `2` (= 2h) |

Unparseable input gets an explicit error ("Couldn't read “…” as a date.") instead of a silent guess, and impossible dates like Feb 30 are rejected rather than rolled over. Project and task **estimates** use the same duration grammar (`40h`, `2h 30m`).

## The Time page

The header shows the week at a glance ("12h 40m this week · 9h 10m billable · $840 unbilled"). Entries are grouped **By day** (Today, Yesterday, weekday names, then "Wed, Sep 2") or **By project**, switched with the segmented control.

The **filter input** matches free text against entry names and understands two prefixes:

- `#tag` — entries carrying that tag
- `@name` — entries whose chain contains a matching project, client or task

Each row shows the name with its tags, the derived chain, the time range, a per-row billable toggle (with "Billable at $…/h" tooltip), duration and amount, and hover actions:

- **▶ Start again** — copies name, reference and billable flag to the timer and starts it.
- **✎ Edit** — opens the manual-entry dialog prefilled; saving PATCHes the entry (removing the chain clears the reference).
- **🗑 Delete** — soft-deletes with an undo toast that counts down visibly.

## Bulk actions

Row checkboxes accumulate a selection; a bar appears above the groups with:

- **Clear** — drop the selection.
- **Mark billable** — set the flag on every selected entry.
- **Move to…** — opens the picker in bulk mode and reassigns every selected entry to the picked client/project/task (or a "No client / project / task" row to clear references). Comes with an undo toast.
- **Delete** — a confirmation dialog states the count, then everything moves to trash with an undo toast.

Undo restores exactly the removed rows. Deleted entries stay in the 30-day [trash](/guide/projects-clients-tasks#trash) like everything else.

### On a phone (<1024px)

Rows collapse to name+chain · duration+range · a single ▶ button, and a **Select** toggle appears in the header (next to Manual entry). Turning it on adds a checkbox to every row and turns off the swipe gestures (a checkbox tap must never be read as a swipe); the bulk bar then shows exactly as it does on desktop, pinned above the docked timer card and tab bar so it's always reachable. The button reads **Done** while active. Turning Select off, or leaving the Time page, clears the selection — it's not saved between visits.

Swipe gestures (left reveals **Delete**, right starts the entry again) work only outside Select mode.

## The undo window

Every undo toast in Tick — entry delete, bulk delete, bulk *Move to…*, tag delete, cascade delete — shares one setting: **Settings → Profile → Undo window**, default **8 seconds**, adjustable from **3 to 30**. The toast shows the remaining seconds as it counts down, and the action is already committed on the server: undo restores, it does not "cancel".

::note
The undo window is stored in the browser's `localStorage`, not on your user row, so it is per-browser rather than per-account. Everything else in Settings → Profile (name, email, default rate) is server-side.
::
